# PBI-002 — Establish product backlog, governance and security

- Feature: F01 Project Foundation
- Priority: P0
- Status: In progress — documentation PR pending review
- Milestone: M0 / M1 governance

## Goal
Maintain product source of truth that Cursor and the GitHub implementation repo can follow without duplicating requirements.

## Scope
- Product charter, six Features, ten PBIs, dependency roadmap, ADRs, workflow, AI instructions.
- Explicit dual-repository boundary and public-repo handling.
- Azure OIDC versus site deploy authorization and secrets versus variables policy.
- Document Azure bootstrap prerequisites without storing subscription IDs or any credentials.

## Out of scope
Terraform apply, creating Azure resources, setting secret values, CI/CD, or producing RPG visuals.

## Acceptance criteria
- Six Feature documents F01-F06 and ten PBI documents PBI-001 through PBI-010 present.
- PO/engineering repo roles agreed, all links/file paths functional.
- Old guidance to create a private repo or publish ZIP is removed from active instructions.
- Sensitive material excluded; documented how to manage secrets, variable identifiers and sensitive Terraform state.
- PR created, reviewed, merged and accepted before state becomes Done.

## Dependencies
PBI-001 repo existence (already achieved); implementation baseline separate.

## Evidence
See PR for documentation changes and security checks. No Azure or app rollout is implied.
